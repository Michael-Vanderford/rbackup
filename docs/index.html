RESTIC BACKUP MANAGER / DEVELOPER REFERENCE

Functions & application flow

A standalone reference for the React frontend and Tauri Rust backend. Open this file directly; no server, build, or external assets are required.

Application flow

UI action → App.run() → invoke("run_restic") → spawn_blocking → execute() → execute_with() → stale-only unlock → restic process → Output → status and output panel

The frontend prevents overlapping actions while busy. The backend retains a process-wide mutex and, on Linux, shares an OS file lock with headless scheduled jobs. Output is captured in full and displayed after completion; there is no streaming. A Cancel operation button requests termination of the app-owned child process.

Exit code 0 produces a green success notice. Code 3 produces an amber incomplete-backup warning; other nonzero codes and invocation failures produce red errors. Running operations are blue. A successful snapshot refresh marks the connection green; disconnected state is amber. JSON parsing failures override command success with an error notice.

Profiles and theme preferences persist in local storage. Typed passwords (unless explicitly saved using Create password file), loaded snapshots, statistics, output, and recent operation history stay in session memory. The theme effect follows system appearance changes when System is selected and removes its listener on cleanup.

src/App.tsx

blank()

Create a new repository profile with a random UUID and empty connection and backup settings.

load()

Load and import saved profiles. Return a blank profile if none exist or storage, JSON parsing, or validation fails.

lines(s)

Split multiline source paths, excludes, or tags into trimmed, nonempty strings.

size(n = 0)

Format a byte count using B, KB, MB, or GB with powers of 1024.

App()

Render the desktop workspace and own theme, profiles, connection, operation, snapshot, restore, and retention state. Browser mode previews the interface without executing restic.

save(next)

Update profile state and persist the supplied profiles in local storage. Storage errors propagate to the caller.

reset()

Clear the session password, loaded repository data, connection status, retention preview, output, and notice when switching profiles. Activity history remains session-wide.

update(key, value)

Persist one field of the active profile. Repository or password-file changes invalidate loaded connection data and retention previews.

run(operation, extra = {})

Invoke run_restic with active credentials and options. Ignore calls while busy; clear previous output, record up to 20 completed process results, and show a success, warning, or error notice. Return the result on exit code 0, otherwise null. Extra options override the standard request fields.

refresh()

Run snapshots and parse its JSON array. Mark the repository connected only on successful parsing, then clear the snapshot selection, file listing, and retention preview.

browse(id)

Select a snapshot directory (root by default), run a nonrecursive ls with an explicit directory filter, parse newline-delimited JSON, remove the directory itself, and sort folders first by name. The browser renders 200 children per page, supports parent navigation and folder reload, and keeps folder navigation separate from the restore include filter. Parsing failures become error notices.

src/profiles.ts

Profile

Persisted profile metadata: id, name, repository, passwordFile, sources, excludes, and tags are strings. Multiline source, exclude, and tag fields are normalized when running commands. Password text is never part of this type.

loadProfiles(storage, imported)

Read and validate the saved profile array, correct the original Full Backup path once from /mnt/backup to /mnt/backup/job_1784917153088_ynpdxm8mc for its known profile ID (preserving custom paths), then merge bundled profiles once by ID. Persist the merged array and import marker. Existing IDs win; later profile removals stay removed. Throws on invalid saved JSON, invalid profile fields, or storage failures.

src-tauri/src/lib.rs

run_restic(request)

Tauri IPC command. Execute the blocking restic work on the async runtime blocking pool and convert worker join failures into string errors. Returns the captured process result or a validation/execution error.

run()

Initialize Tauri, register the opener plugin and run_restic command, then enter the application event loop. Panics if the Tauri application cannot run.

src-tauri/src/restic.rs

Request

Deserialize the frontend command payload using camelCase field names. repository, password, passwordFile, and operation are required; other fields default to empty strings, empty arrays, false, or zero. See the operation table for conditional requirements.

Output

Captured stdout and stderr as UTF-8 strings, replacing invalid bytes, plus the process exit code. A missing exit code is represented by -1. A nonzero exit is returned as output rather than a Rust error.

snapshot(value)

Validate a snapshot identifier as 8 through 64 ASCII hexadecimal characters. Return a user-facing error for invalid identifiers.

arguments(r)

Validate an allowlisted operation and construct separate restic arguments without a shell. Returns a user-facing error for unsupported operations or invalid credentials, paths, snapshot IDs, retention values, or confirmations. Performs filesystem checks for backup and restore paths.

execute(r)

Acquire a process-wide nonblocking job lock, validate arguments, and run restic from PATH with stdin closed. Remove inherited RESTIC_PASSWORD_COMMAND, RESTIC_PASSWORD_FILE, and RESTIC_PASSWORD; set the request password only when no password file is supplied. Capture output until exit. Validation, lock, and process launch failures return string errors; nonzero process exits remain Output values.

Password-file creation

App.createPasswordFile() sends the session password and profile ID to create_password_file(app, profile_id, password), a Tauri command using the blocking pool. password_file::create(path, password) validates an absolute path and a nonempty single-line password, then exclusively creates a new file with Unix mode 0600. It writes the exact password bytes and syncs the file; write failures trigger best-effort removal of the partial file. For the Create action, create_managed(home, profile_id, password) validates the profile ID, creates an owner-only (0700) directory under ~/.local/share/tauri-backup-manager/passwords, and creates <profile-id>.password. The command returns the absolute path, which the frontend persists in the profile. Existing files and symlinks are refused. Non-Unix platforms return an unsupported error rather than creating a file without private permissions. The action shows success or failure through the existing status banner.

Cancellation

App.cancelOperation() invokes cancel_restic(), which calls restic::cancel() to flag the current operation. execute() installs and clears the shared flag while holding the job mutex. capture_command() drains stdout and stderr concurrently, polls child status and cancellation, and reaps the child before returning. Unix cancellation sends SIGINT, then forces termination after ten seconds; other platforms terminate directly. Cancellation returns code 130, including during preflight cleanup, and prevents the requested operation from starting after cancelled cleanup. The frontend displays amber cancellation and clears loaded repository data. Already completed changes are not rolled back.

Backend execution helpers

execute_with(r, run) validates the requested operation, runs stale-only cleanup when applicable, and invokes the operation only after successful cleanup. The injected runner supports tests without touching repositories. run_command(r, args) configures credentials and captures one restic process. arguments() also permits unlock without force options.

Frontend entry point

src/main.tsx mounts App in React StrictMode. src/App.css provides responsive layout, light/dark themes, semantic status colors, focus indicators, and reduced-motion spinner behavior.

Linux backup scheduler

UI and command boundary

SchedulePanel edits daily/weekly local schedules and polls status every five seconds without replacing unsaved edits. schedulerAction() calls the asynchronous Tauri scheduler_action command with status/save/sync/remove/cancel actions, a profile ID, and optional profile/schedule metadata. A schedule contains enabled, frequency, time (HH:MM), and weekdays (Monday=0 through Sunday=6). All schedules default to daily 03:00 disabled. Password text is never accepted by this boundary.

Configuration and systemd lifecycle

scheduler::save() validates backup settings, password-file readability, and the native calendar; resolves absolute restic/app executable paths; atomically saves private metadata; and installs the per-profile service/timer. Failed installations restore previous files and timer state where possible. sync() updates saved backup metadata and disables invalid schedules. remove() stops the timer/service before deleting managed configuration. status() reads next occurrence, service state, last result, and bounded journal output. cancel() stops queued or active service work. Linux uses persistent user timers; other platforms retain manual backups.

Headless execution and coordination

headless() dispatches --scheduled-backup <profile-id> before Tauri initialization. scheduler::run() installs signal handlers, records waiting/running/final status, and runs a real backup with the saved password file. coordination::acquire() holds a shared advisory file lock for manual and scheduled operations across processes. Scheduled work waits interruptibly; interactive work reports busy. Once the lock is acquired, the runner reloads current settings, validates mounts/sources/credentials, performs stale-only cleanup, and captures backup output for the journal. SIGINT/SIGTERM request graceful cancellation with the existing ten-second forced-termination fallback. Finished changes are not rolled back.

Files and tests

Private configuration and last-run files live under ~/.local/share/tauri-backup-manager/schedules; systemd units live under the user's systemd configuration directory. Output remains in the user journal. src-tauri/tests/scheduler_headless.rs covers real disposable backup creation, argument forwarding, concurrent runners, queued/running cancellation, and headless validation. Unit tests cover calendars, escaping, private storage, rollback, edit synchronization and removal using a subprocess with fake systemctl. Optional checks validate actual units and exercise real runtime timers with one missed-run catch-up. See README for commands, deployment path requirements, remote credential environment differences, and login-session limits.

Supported operations

Before existing-repository operations, including previews, the backend runs restic unlock with the same credentials. Restic decides which locks are stale; --remove-all is never used. Cleanup failure aborts the operation. Initialization, version checks, and direct unlock skip this preflight. Cleanup output is kept separate from operation JSON.

All operations except version require a repository and either a password or password-file path. A supplied password file takes priority.

OperationRequirements & behavior
versionNo repository or credentials required.
init / snapshots / statsRepository and password or password file required; JSON output requested.
backupAt least one existing absolute source path. Optional excludes, tags, and dryRun. Source paths follow --.
lsValid snapshot ID and an optional absolute directory (defaults to /). Lists only immediate children as newline-delimited JSON without --recursive; rejects parent traversal.
restoreValid snapshot ID and absolute target that is new or empty. Always uses --verify and --overwrite never. Optional include pattern.
checkOptional readData enables --read-data.
forgetAt least one positive retention count; each count at most 10000. dryRun previews; applying requires confirmation FORGET.
pruneRequires confirmation PRUNE; reclaims unreferenced data.

The UI requires a matching retention preview before applying a policy. The backend validates counts and confirmation independently; it does not track whether a preview occurred.

Optional automatic maintenance runs after successful non-dry-run backups: check, forget with a per-profile saved retention policy, then prune. A failed step stops later steps; the operation lock spans the entire sequence. Profiles without a maintenance policy retain manual-only behavior.

Maintaining documentation

Source comments use TypeScript JSDoc (/** … */) and Rust rustdoc (///) so editors show documentation beside the code. Update this page whenever function contracts or operation rules change; this overview is maintained manually.

For generated Rust API pages, run cargo doc --manifest-path src-tauri/Cargo.toml --no-deps --document-private-items and open src-tauri/target/doc/tauri_backup_manager_lib/index.html (unless a custom Cargo target directory is configured). This optional command requires the Rust/Tauri build prerequisites.

Checks: npm run build validates frontend compilation; node tests/profiles.test.ts checks profile import behavior. Rust validation: cargo test --manifest-path src-tauri/Cargo.toml --lib. The ignored lifecycle test requires restic on PATH and uses a disposable temporary repository.
